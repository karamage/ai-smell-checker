# NIOU（ニオウ）AI臭い文章チェッカー 設計書

作成日: 2026-09-17

## 1. 目的

日本語の文章を貼り付けると、「AIが書いた感」の出る箇所を静的解析で列挙し、
臭気レベルとして可視化する Web アプリ。Cloudflare Workers 上で動く。

アピールしたい点は 4 つ。技術力、パッと見のインパクト、SNS 映え、GitHub でスターが付きやすいこと。

## 2. 名前とコンセプト

- 名前: NIOU（匂う）。ロゴは 👃。
- コンセプトは「文章の臭気検査」。結果を 0〜100 の「臭気指数」と 5 段階の「臭気レベル」で返す。
- 本文はブラウザ内で解析し、サーバーには送りません。

臭気レベル（指数が高いほど AI 臭い）

| 指数 | レベル | 表示 |
|---|---|---|
| 0〜14 | Lv.0 無臭 | 🌿 人の手の匂いがする |
| 15〜34 | Lv.1 微臭 | 🍃 ほんのり AI の香り |
| 35〜54 | Lv.2 匂う | 👃 鼻が気づくレベル |
| 55〜74 | Lv.3 臭い | 🤢 換気が必要 |
| 75〜100 | Lv.4 激臭 | ☠️ 生成物です |

## 3. 検査ルール（静的解析）

入力は日本語のプレーンテキストまたは Markdown。出力は `Finding[]`。
各 Finding は `ruleId`、`severity`（high / mid / low）、`message`、`range`（文字オフセット start/end、文書全体の指摘なら null）、`excerpt`、`hint` を持つ。

| ID | ルール | 判定方法 | 対象 |
|---|---|---|---|
| R0 | 禁止ワード | 辞書（約 100 パターン）との部分一致。語ごとに重み high/mid/low | 範囲 |
| R1 | 「です」「ます」の 3 連続 | 文末を正規化し、同一文末（です／ます）が 3 文以上連続したら指摘 | 範囲（連続区間） |
| R2 | 箇条書き 3 個以上の連続 | 行頭が `-` `*` `・` `•` `数字.` `数字)` `①` 等の行が 3 行以上連続 | 範囲（ブロック） |
| R3 | 「〜と言えるでしょう」「〜ではないでしょうか」 | 正規表現（表記ゆれ含む） | 範囲 |
| R4 | 段落の長さにバラつきがない | 段落（空行区切り）が 3 個以上あり、推定行数（40 字＝1 行）の変動係数が 0.35 未満、または 1 行段落が 1 つもない場合に指摘 | 文書全体 |
| R5 | 「まず」「次に」「最後に」で段落が始まる | 段落先頭の接続詞（まず／まずは／次に／最後に／続いて） | 範囲 |
| R6 | 失敗・迷い・未解決の話がない | 失敗語彙（失敗／ハマった／詰まった／わからない／迷った／未解決／できなかった など約 40 語）が 1 つも無ければ指摘 | 文書全体 |
| R7 | 主語がない | 一人称主語（私は／自分は／僕は／我々は／このブログでは／筆者は など）が 1 つも無ければ指摘 | 文書全体 |
| R8 | 同じ口語表現を 2 回以上 | 口語辞書（正直／ぶっちゃけ／めちゃくちゃ／ちなみに／〜ですよね など約 40 語）で 2 回以上出た語の 2 回目以降を指摘 | 範囲 |
| R9 | 見出し直後が説明 | Markdown 見出し（`#`）または短い単独行の直後の最初の文が「〜とは」「〜について」「説明します」「紹介します」「見ていきましょう」等で始まる／終わるなら指摘 | 範囲 |
| R10 | 文のリズムが単調 | natural-japanese の統計検出器を文字数ベースで移植。文長の burstiness（(σ−μ)/(σ+μ) < −0.24）または変動係数 < 0.25、隣接文長の lag-1 自己相関 > 0.6、段落あたり文数の変動係数 < 0.15、同じ型の文末（た形・る形など）が 5 文連続、同じ文頭 2 文字が 5 文以上。文が 6 未満なら評価しない | 文書全体（文末連続・文頭反復は範囲） |
| R11 | AI が好む構文 | 文単位の正規表現。「単なるAではなく、Bなのです」「Aではなく、Bである」「Aであり、Bであり、Cである」「Aすることで、Bできる」「ここで大事なのは〜」は 1 文 1 件。「一方で〜。しかし〜。だから〜」は接続詞で始まる文が 3 文連続したとき | 範囲 |
| R12 | 変な比喩 | 14 語の比喩辞書。羅針盤・車の両輪・潤滑油は常に、土台・柱・筋トレ・スパイス・DNA は「〜の◯◯」か述語付き、地図・仕様書・設計書・栄養・筋肉・エンジン・レシピは「◯◯となる／である／のような」の述語付きのときだけ比喩とみなす | 範囲 |

### 臭気指数の計算

各ルールに上限点を持たせ、指摘数に応じて加算する。合計を 0〜100 に切り詰める。

| ルール | 1 件あたり | 上限 |
|---|---|---|
| R0 high / mid / low | 8 / 4 / 2 | 30 |
| R1 | 8 | 16 |
| R2 | 6 | 12 |
| R3 | 8 | 16 |
| R4 | 10 | 10 |
| R5 | 5 | 10 |
| R6 | 10 | 10 |
| R7 | 8 | 8 |
| R8 | 3 | 9 |
| R9 | 5 | 10 |
| R10 high / mid / low | 10 / 6 / 3 | 16 |
| R11 high / mid / low | 8 / 5 / 3 | 16 |
| R12 high / mid | 7 / 5 | 15 |

短い文書（400 字未満）はルール R4／R6／R7／R10 の文書全体ルールを適用しない（短文では判定できないため）。100 字未満は「短すぎる」として指数を出さない。

## 4. AI 二次審査

当初は Workers AI（Qwen3）による意味判定を載せていたが、2026-09-17 に不要と判断して削除した。サーバー側の解析は静的ルールだけで完結する。

## 5. SNS 共有

- 結果から共有コードを作る。`score`、`level`、ヒットしたルール ID のビットマスク（v3 は 16 ビットで 8 文字。5 byte 形式の v1／v2 も読める）、指摘件数を base64url でエンコードした文字列。本文は含めない。
- `GET /r/:code` は共有ページ。OG メタタグ（`og:image` に `/og/:code.png`）を付けた HTML を返し、結果カードと「自分の文章も検査する」導線を出す。
- `GET /og/:code.png` は `workers-og`（Satori + resvg）で 1200×630 の結果カードを生成する。日本語フォントは Google Fonts の Noto Sans JP を実行時に取得し、Cache API でキャッシュする。
- クライアントには「X で共有」「画像を保存」「URL コピー」の 3 ボタンを置く。画像保存は OG 画像 URL をそのままダウンロードする。

## 6. 画面設計

ダークテーマ。背景は黒に近い紺、アクセントは毒々しい黄緑（#b6ff3b）、臭気は紫の煙。

1. ヒーロー: 巨大な「NIOU」ロゴと 1 行のコピー「その文章、AI臭くない？」。
2. エディタ: 左にテキストエリア（貼り付け即解析、300ms デバウンス）。テキストエリアの背面に同じ文字組みのミラー層を敷き、指摘箇所をルール色でマーカー表示する。
3. 臭気計: 右に半円ゲージ。数値がカウントアップし、レベルに応じて色と絵文字が変わる。背景の Canvas に煙パーティクルが漂い、指数が上がるほど濃くなる。
4. 指摘リスト: ルール別のカードを縦に並べる。クリックでエディタの該当箇所へスクロール。
5. AI に直させるプロンプト: 指摘ルールごとの該当箇所と直し方、言い換えで入れてはいけない表現、本文を 1 つのプロンプトに組み立てて表示。コピーと ChatGPT／Claude への受け渡しリンク。
6. 共有バー: 結果カードのプレビューと 3 ボタン。
7. サンプル投入ボタン: 「AI臭いサンプル」「人間っぽいサンプル」を 1 クリックで流し込み、初見でも遊べる。

すべてスマホ幅で 1 カラムに落ちる。

## 7. アーキテクチャ

```
src/
  core/            解析エンジン。DOM も Cloudflare API も使わない純 TypeScript
    index.ts       analyze(text) => Report
    types.ts
    segment.ts     文・段落・行・見出しの分割（文字オフセット付き）
    score.ts       臭気指数とレベル
    share.ts       共有コードのエンコード／デコード
    prompt.ts      書き直し用プロンプトの組み立て
    dict/          禁止語、失敗語彙、主語、口語の辞書
    rules/         r0〜r9 を 1 ファイル 1 ルール
  worker/          Hono アプリ
    index.ts       ルーティング。/api/*、/r/*、/og/* 以外は静的アセット
    share.tsx      共有ページ HTML
    og.tsx         OG 画像
  client/          React 19
    main.tsx, App.tsx, components/, hooks/, styles.css
  cli.ts           bun run cli <file> で同じエンジンを CLI 実行
```

- ビルド: Vite 8 + `@cloudflare/vite-plugin`。クライアントは `dist/client`、Worker は `dist/niou`。
- 静的アセット: `not_found_handling: "single-page-application"`、`run_worker_first: ["/api/*", "/r/*", "/og/*"]`。
- 型: TypeScript 7（ネイティブ tsc）。`tsc --noEmit` で検査。
- Lint／整形: Biome（フォーマット＋import 整理）と oxlint（型認識なしの高速 lint）。
- テスト: `bun test`。core は各ルールにサンプル文でのユニットテスト、Worker は `app.request()` で API のスモークテスト。

## 8. エラー処理

- 空文字／100 字未満: UI は指数を出さず「もう少し書いてね」と表示。
- 共有コードが壊れている: `/r/:code` は 404 ページ、`/og` は 404。
- OG フォント取得失敗: 502 を返しつつ、共有ページ自体は表示できる。

## 9. スコープ外

- 本文の保存（KV／D1）。共有は本文を含まない。
- 認証、履歴、複数言語対応。
- ブラウザ拡張。
